# AuditForge: 6 идей, как усилить проект

Контекст: хакатон, кейс «RL-среды для дообучения моделей финансового аудита» (FinTech, сдача до 22 ноября 2026, 23:59 по Астане).
Жюри оценивает корректность среды и оценщика, а не награду агента. Идеи ниже отсортированы от самых полезных для баллов к самым эффектным для показа.

## 1. Фаззер взлома награды
Скрипт сам генерирует тысячи странных ответов: случайные ID, дубли, пустые доказательства, огромные суммы, чужие документы.
Он ищет ответ, который получит награду выше честного. Если такого нет, это прямое доказательство надёжности награды.
Бьёт в критерий «Надёжность награды» (25 баллов).

## 2. Граф причин для демо
Картинка одной цепочкой: платёж → неверная дата → неверный курс → расхождение в суммах.
Жюри сразу видит, что ошибки в эпизоде связаны причинно, а не раскиданы случайно. Данные для графа уже есть в `provenance.json` (`causal_links`).

## 3. Адаптивная сложность
Среда смотрит, какие ошибки политика находит хуже всего, и генерирует больше таких случаев.
Это настоящий учебный план для RL. Типы ошибок не меняются, меняется только их частота и сочетания.

## 4. Режим «судья по доказательствам»
Награда за вывод зависит от того, насколько короткий и точный набор документов приложен.
Агента перестают поощрять за «свалить всё в кучу». Важно оставить общую награду из кейса без изменений и показывать эту отдельно.

## 5. Отчёт по эпизоду для человека
По каждому эпизоду автоматически собирается короткий отчёт: что было сломано, как это найти, где ловушка.
Полезно для защиты и для понимания, где среда действительно сложная.

## 6. Мини-обучение на CPU
Крошечная политика учится на десятке эпизодов, потом проверяется на отложенных. Баллов не даёт, но красиво в демо.
Осторожно: без честного контролируемого сравнения на отложенных данных заявлять улучшение нельзя.

## Рекомендация
Если выбирать две: идеи 1 и 2. Первая добавляет баллы, вторая добавляет эффект на показе.
